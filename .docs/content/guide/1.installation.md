# Setup ArmoniK SDK

## Global prerequisites

- CMake minimum version 3.22
- gRPC minimum version 1.50 (installed or built from source)
- [ArmoniK API](https://github.com/aneoconsulting/ArmoniK.Api) latest version installed
- [nlohmann/json](https://github.com/nlohmann/json) ≥ 3.11 (required for the convention execution path; available as `nlohmann-json3-dev` on Debian/Ubuntu or built from source on RHEL/UBI)

## How to build for Linux

### Prerequisites Linux

1. Install Docker on your Linux system. Follow the instructions on the [official Docker documentation](https://docs.docker.com/engine/install/).
2. Clone the repository containing the source code and the necessary scripts.
3. In a Linux terminal:
    - Define the `ARMONIK_API_DIR` environment variable to point to the installation directory of ArmoniK API. If this variable is not defined, it is assumed
     that the ArmoniK.Api cpp installation directory is located at the same level where the current repository was cloned, that is: `../ArmoniK.Api/packages/cpp/install`.
    - Run the utility script:
    ```bash
      $ ./tools/setup-remote.sh
    ```

### CLion setup
- In a Linux terminal:
  ```bash
    ./tools/restart-build-env.sh
  ```
- In your IDE:
  - Setup ``Remote Host`` as your toolchain and specify the user as ``root``, password as ``password`` and the address and ports to match the REMOTE_BUILD_ADDRESS variable specified in the script.

### Visual Studio setup
  - In the remote explorer menu (left panel), you can search and connect to the `armonik_sdk_build_visual_studio` container:

  ![](https://armonik-public-images.s3.eu-west-3.amazonaws.com/armonik_sdks_doc/cpp/dev-container.png)

  - _Note: As the project source is mounted in the docker, you may want to disable the file copies for ``rsync``._

## How to build for Red Hat Enterprise Linux 8 / UBI 8

RHEL 8 ships without a system gRPC package. The recommended and tested approach is to use the pre-built static RPMs published at [aneoconsulting/grpc-rpm](https://github.com/aneoconsulting/grpc-rpm). Because these libraries are compiled statically, some bundled dependencies (Abseil, Protobuf, c-ares) must also be linked statically into your binaries. ArmoniK.Api handles this automatically on Red Hat systems as of [ArmoniK.Api v3.29.0](https://github.com/aneoconsulting/ArmoniK.Api/releases/tag/3.29.0) — consumer projects inherit the required static link flags through the CMake package config mechanism.

No RHEL subscription is required; all packages come from the UBI 8 base image and the EPEL repository, which are freely available.

### 1. Enable EPEL and install system dependencies

```bash
rpm -ivh https://dl.fedoraproject.org/pub/epel/epel-release-latest-8.noarch.rpm

yum --disableplugin=subscription-manager install -y \
    make cmake git gcc gcc-c++ wget \
    libcurl-devel simdjson-devel re2-devel \
    zlib-devel openssl-devel
```

### 2. Build and install nlohmann/json from source

nlohmann/json is not available as an EPEL package and must be compiled from source:

```bash
git clone --depth 1 https://github.com/nlohmann/json.git -b v3.11.3 /tmp/nlohmann-json
cmake -S /tmp/nlohmann-json -B /tmp/nlohmann-json/build \
    -DCMAKE_INSTALL_PREFIX=/usr/local \
    -DJSON_BuildTests=OFF
cmake --build /tmp/nlohmann-json/build --target install
```

### 3. Install the gRPC RPMs

Download the `grpc` and `grpc-devel` packages from the [grpc-rpm releases](https://github.com/aneoconsulting/grpc-rpm/releases). The release tag appends an extra `.x` build counter to the gRPC version (e.g. `1.62.2.0` for gRPC `1.62.2`, first build).

```bash
GRPC_BUILD=1.62.2.0           # check releases for the latest tag
GRPC_VER=${GRPC_BUILD%.*}     # strips the build counter → 1.62.2

wget "https://github.com/aneoconsulting/grpc-rpm/releases/download/${GRPC_BUILD}/grpc-${GRPC_VER}-1.el8.x86_64.rpm"
rpm -ivh "grpc-${GRPC_VER}-1.el8.x86_64.rpm"

wget "https://github.com/aneoconsulting/grpc-rpm/releases/download/${GRPC_BUILD}/grpc-devel-${GRPC_VER}-1.el8.x86_64.rpm"
rpm -ivh "grpc-devel-${GRPC_VER}-1.el8.x86_64.rpm"
```

The packages install under `/usr/local/grpc`; pass `-DCMAKE_PREFIX_PATH=/usr/local/grpc` to CMake so it can locate the gRPC config files.

> **Note:** The RPMs bundle Abseil, Protobuf, and c-ares as static archives. Do not mix these with separately installed shared versions of those libraries.

### 4. Install ArmoniK.Api

Download the RPM from [ArmoniK.Api releases](https://github.com/aneoconsulting/ArmoniK.Api/releases):

```bash
API_VERSION=<version>
wget "https://github.com/aneoconsulting/ArmoniK.Api/releases/download/${API_VERSION}/libarmonik-${API_VERSION}-Linux.rpm"
rpm -ivh "libarmonik-${API_VERSION}-Linux.rpm"
```

### 5. Build the SDK

```bash
cmake -S /path/to/ArmoniK.Extensions.Cpp -B build \
    -DCMAKE_BUILD_TYPE=Release \
    -DCMAKE_PREFIX_PATH=/usr/local/grpc \
    -DARMONIK_API_DIR=/armonik/api \
    -DBUILD_CLIENT=OFF \
    -DBUILD_DYNAMICWORKER=ON \
    -DBUILD_END2END=OFF

cmake --build build -j$(nproc)
cmake --install build
```

The static gRPC RPMs are built with `BUILD_SHARED_LIBS=OFF`. ArmoniK.Api detects Red Hat at configure time and automatically links the required Abseil static libraries; no extra flags are needed in the SDK's own CMakeLists.

## Worker Docker images

Pre-built dynamic worker images are available on [Docker Hub (dockerhubaneo/armonik-sdk-cpp-dynamicworker)](https://hub.docker.com/r/dockerhubaneo/armonik-sdk-cpp-dynamicworker) for the following base platforms:

| Tag suffix | Base image | Notes |
|---|---|---|
| *(none / default)* | Ubuntu | General-purpose Linux |
| `-ubi8` | RHEL 8 / UBI 8 | For RHEL-based deployments |

The RHEL8 image installs nlohmann/json from source and obtains gRPC from pre-built RPM packages; no RHEL subscription is required for the UBI8 base layer.

## How to build for Windows (Client only)

No Windows binaries are published. The Client and Common libraries are built from source with MSVC, using the script `tools/windows/build.ps1`. The `build-windows-msvc` CI job runs this same script on every pull request, then builds and runs a small downstream project against the installed SDK, so the steps below are tested. The Worker and DynamicWorker are not supported on Windows.

### Prerequisites Windows

- Visual Studio 2022 with the "Desktop development with C++" workload
- CMake ≥ 3.22 and Git on `PATH`
- gRPC (≥ 1.50), Protobuf, Abseil, nlohmann/json and zlib built with MSVC, from either:
  - [micromamba](https://mamba.readthedocs.io/en/latest/installation/micromamba-installation.html) (or conda/mamba), as in step 1. This is the setup tested in CI.
  - Your own install (vcpkg, source builds), as long as it provides CMake config files. Skip step 1 and see [Using your own dependencies](#using-your-own-dependencies).

With conda, the dependencies come as prebuilt MSVC binaries from conda-forge. Their versions are pinned in `tools/windows/environment.yml` and match the ones used in CI. ArmoniK.Api is built from source by the script, at the version set in `tools/common.sh`.

### 1. Create the dependency environment (conda)

From the repository root, in PowerShell:

```powershell
micromamba create -f tools\windows\environment.yml
micromamba activate armonik-sdk-windows
```

### 2. Build and install

```powershell
.\tools\windows\build.ps1 -Prefix C:\armonik -Verify
```

This clones and builds ArmoniK.Api, builds the SDK, and installs both into `C:\armonik`. `-Verify` then builds and runs `tools\windows\consumer` against the installation.

If PowerShell refuses to run the script, allow local scripts for the current session first: `Set-ExecutionPolicy -Scope Process RemoteSigned`.

| Option | Default | Description |
|---|---|---|
| `-Prefix` | `<repo>\install-windows` | Install directory for ArmoniK.Api and the SDK |
| `-DepsPrefix` | `$env:CONDA_PREFIX` | Root of the conda environment, needed if it is not activated |
| `-DepsCMakePrefix` | none | CMake prefix of your own dependencies, used as is. Overrides `-DepsPrefix` |
| `-WorkDir` | `<repo>\build-windows` | Build directory |
| `-ApiVersion` | `ARMONIK_API_VERSION_DEFAULT` in `tools/common.sh` | ArmoniK.Api tag to build |
| `-ApiSource` | clone into `-WorkDir` | Existing ArmoniK.Api checkout to use instead |
| `-Version` | `ARMONIK_SDK_VERSION_DEFAULT` in `tools/common.sh` | SDK version embedded in the build |
| `-Config` | `Release` | `Release`, `RelWithDebInfo` or `MinSizeRel` |
| `-Verify` | off | Build and run the consumer project after installing |

### Using your own dependencies

Pass the prefix that contains the dependencies' CMake config files with `-DepsCMakePrefix`. For vcpkg:

```powershell
vcpkg install grpc protobuf abseil nlohmann-json zlib --triplet x64-windows
.\tools\windows\build.ps1 -Prefix C:\armonik -DepsCMakePrefix C:\vcpkg\installed\x64-windows -Verify
```

The script puts `<DepsCMakePrefix>\bin` on `PATH`. If `protoc` or `grpc_cpp_plugin` live elsewhere (vcpkg keeps them in `tools\protobuf` and `tools\grpc`), make sure CMake can find them, for example by adding those directories to `PATH`.

Without the script, the equivalent commands are:

```powershell
$DEPS = "C:\vcpkg\installed\x64-windows"   # your dependency prefix
$PREFIX = "C:\armonik"                       # install prefix
$env:PATH = "$DEPS\bin;$env:PATH"

git clone --depth 1 --branch <api-version> https://github.com/aneoconsulting/ArmoniK.Api.git
cmake -S ArmoniK.Api\packages\cpp -B build\api -DBUILD_CLIENT=ON -DBUILD_WORKER=OFF -DBUILD_TEST=OFF "-DCMAKE_PREFIX_PATH=$DEPS"
cmake --build build\api --config Release --parallel
cmake --install build\api --config Release --prefix $PREFIX

cmake -S . -B build\sdk "-DARMONIK_API_DIR=$PREFIX" "-DCMAKE_PREFIX_PATH=$DEPS" -DBUILD_WORKER=OFF -DBUILD_DYNAMICWORKER=OFF
cmake --build build\sdk --config Release --parallel
cmake --install build\sdk --config Release --prefix $PREFIX
```

`<api-version>` is `ARMONIK_API_VERSION_DEFAULT` in `tools/common.sh`. Only the conda-forge versions in `environment.yml` are tested in CI.

### 3. Use the SDK in your project

```cmake
find_package(ArmoniK.SDK.Client CONFIG REQUIRED)
target_link_libraries(my_app PRIVATE ArmoniK.SDK.Client)
```

Configure with both the install prefix and the dependency prefix on the prefix path (`$env:CONDA_PREFIX\Library` with conda, the `-DepsCMakePrefix` value otherwise):

```powershell
cmake -S . -B build "-DCMAKE_PREFIX_PATH=C:\armonik;$env:CONDA_PREFIX\Library"
cmake --build build --config Release
```

`tools\windows\consumer` is a minimal working example.

### Notes

- **Build type.** Build your application in `Release` or `RelWithDebInfo`, not `Debug`. The conda-forge libraries are built against the release C runtime (`/MD`). Linking them into code compiled with the debug runtime (`/MDd`) fails with `LNK2038` mismatches or crashes at run time.
- **Run time DLLs.** The SDK libraries are static, but gRPC, Protobuf and Abseil are DLLs, in `<env>\Library\bin` with conda or `<prefix>\bin` with vcpkg. Put that directory on `PATH` when running your application, or ship those DLLs next to it.
